# 頁面文字：八成 ASD-STE100

> SKILL.md § 輸出階梯 的寫作規則細節。頁面上給人讀的字（標題、說明、卡片、圖上標籤、旁白）都照這份寫。

## 這是什麼

ASD-STE100（Simplified Technical English）是航太維修手冊用的「受控英文」：限定句長、一句一事、主動語態、一詞一義。目的是讓非母語、趕時間、在現場的人一次讀懂、不會讀錯。

我們只取**八成**：拿它的寫作規則，不拿它的字典（STE 有一份核准詞表，中文頁面用不上）。剩下兩成留給語氣與上下文——頁面不是維修手冊，太硬會讀起來像機器人。

## 八條規則（濃縮版）

| # | 規則 | 中文頁面怎麼做 |
|---|---|---|
| 1 | **短句** | 說明句 ≤ 25 字，步驟句 ≤ 20 字。超過就拆成兩句 |
| 2 | **一句一事** | 一句只講一個動作或一個事實。「並且」「同時」「此外」連起來的句子，拆開 |
| 3 | **主動語態** | 寫出誰做什麼：「系統寄出通知」，不寫「通知被寄出」「通知會由系統進行寄送」 |
| 4 | **一詞一義、一義一詞** | 同一個東西全頁只用一個名字。第一段叫「訂單」，後面不要變「單據」「order」 |
| 5 | **術語先定義** | 第一次出現的專有名詞，同句或下一句用白話講它是什麼。講不出來就換掉 |
| 6 | **動詞放前面** | 步驟與指示以動詞開頭：「按下送出」「確認金額」。不寫「接下來您可以進行送出的動作」 |
| 7 | **少用虛詞與名詞化** | 刪「進行」「做一個」「的部分」「相關」「基本上」；「進行驗證」→「驗證」 |
| 8 | **具體數字取代形容詞** | 「很快」→「3 秒內」、「很多」→「約 200 筆」。不知道數字就不要形容 |

**例外（那兩成）**：開場一句話可以有語氣、類比段可以用比喻、引用原文照抄。程式碼、指令、欄位名不受這些規則管。

## 套用到每一層輸出

| 輸出 | 怎麼套 |
|---|---|
| 圖上標籤 | 名詞片語 ≤ 8 字；箭頭標籤用動詞（「寄出」「回傳」） |
| 一頁版 takeaway | 每條一句、≤ 25 字、以結論開頭 |
| 頁面段落 | 每段 ≤ 4 句；每句 ≤ 25 字 |
| 影片旁白 | 每句 ≤ 20 字（念起來約 4 秒）；每幕 ≤ 3 句、≤ 15 秒；不用括號（念不出來） |

## 前後對照

**例 1：被動 + 名詞化 + 一句多事**

> ✗ 在使用者完成付款之後，訂單狀態會被系統進行更新，並且相關的通知也會同時被寄送給客服人員以便進行後續處理。
>
> ✓ 使用者付款後，系統把訂單改成「已付款」。系統再寄通知給客服。客服接著出貨。

**例 2：術語沒定義 + 換名字**

> ✗ 這次改動主要影響 idempotency key 的處理，重送的 request 會被擋下，避免重複扣款的單據產生。
>
> ✓ 每筆付款帶一個「防重號碼」（idempotency key）。同一個號碼送第二次，系統直接擋掉。所以客戶不會被扣兩次款。

**例 3：形容詞取代數字（旁白）**

> ✗ 快取可以讓整體效能大幅提升，回應速度會變得非常快。
>
> ✓ 有快取時，回應從 800 毫秒降到 40 毫秒。

## 自查（寫完掃一遍）

- 有沒有句子超過 25 字？拆。
- 有沒有「被」「進行」「相關」「的部分」？改主動、刪虛詞。
- 同一個東西有沒有兩個名字？統一。
- 每個英文術語第一次出現時，旁邊有沒有白話？
- 旁白念一遍：有沒有一口氣念不完的句子？

中英混雜詞仍照 `cn-en-translation-checklist.md` 處理；兩份不衝突——那份管「用哪個字」，這份管「句子怎麼組」。
